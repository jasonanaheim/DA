# SEO

Baseline: 2026-09-02; source: all seven HTML files, shared header, CSS asset references, README, tracked-file inventory.

## Purpose

Document current discoverability and future quality requirements without adding SEO features.

## User goal

Find the relevant local business and land on an accurate, useful page.

## Business goal

Attract qualified local visitors who can complete an external booking.

## Current implementation

All seven documents have lang=en, UTF-8, viewport metadata, a title and description. Home, About, Gallery, Pricing have tailored descriptions; Contact, FAQ and legacy booking share a generic mobile-service description. Six main pages have one H1; legacy booking has none.

No canonical links, Open Graph/Twitter metadata, JSON-LD/schema, sitemap, robots.txt, verification tags, or first-party analytics found. No redirect/server/header configuration found. Their absence in source is not proof that production hosting never supplies them.

Main content is static HTML; navigation is generated by JavaScript in Shadow DOM. Internal text links also appear in bodies/footers. Legacy Contact/FAQ Home paths and asset casing are invalid against tracked files. Root and index.html both exist as local entry URLs; canonical host/path policy is TBD.

Images generally have alt text but several Home preview labels mismatch subjects. Most lack intrinsic width/height and srcset; gallery later images and Maps iframes are lazy. Homepage map has an embed key without a title; About map is titled/keyless. Maps, fonts, legacy scheduling/email/CDNs make third-party requests.

## Required content/sections

Preserve present titles, descriptions and visible local-service text unless a content spec authorizes changes. Public domain, canonical host, address visibility, business hours, exact coverage, Google Business Profile, indexing policy and social-preview asset are TBD.

Existing reviews and service claims must not be converted into invented AggregateRating, LocalBusiness fields, guarantees or unsupported service-area pages.

## Primary CTA

SEO serves Book Now conversion; preserve direct external booking access and useful pricing/contact paths. See [book-now.md](book-now.md).

## Functional requirements

Future approved SEO work must use confirmed production URLs, correct source routes, accurate metadata and verified business facts. Do not guess canonical URLs, generate fictitious city landing pages, or add the legacy booking route to sitemap/schema without a lifecycle decision. Preserve crawlable body content and usable internal links.

## Mobile requirements

Local landing pages must remain readable, fast, and navigable on phones. Measure actual served assets/rendering before optimization; total media repository size is not mobile transfer size.

## Accessibility requirements

Use correct heading hierarchy, descriptive alt text, useful links, and navigable disclosures; keyword stuffing or hidden search-only content is not acceptable. Passing SEO checks does not establish accessibility compliance.

## SEO requirements

Future scope should separately decide canonical/indexing policy, metadata uniqueness, sitemap/robots, appropriate factual structured data, social previews, and Search Console verification. None are implemented by this spec. Production status codes, HTTPS redirects, crawlability/indexation, Core Web Vitals and search traffic baseline are TBD.

## Acceptance criteria

- Current metadata inventory and absent features are documented without claiming production verification.
- Any approved SEO additions use owner-confirmed domain/business facts and actual accessible pages.
- Links/assets use correct case and no nonexistent local routes; existing violations remain logged until approved repair.
- No invented ratings, policy/address claims, service areas or search-result guarantees.
- For a future change, record before/after metadata, route/link validation, mobile checks and production verification when authorized.

## Out of scope

Implementing metadata/schema/sitemap/robots, adding analytics, creating SEO pages, changing copy, accessing search accounts, deploying, or provider migration.
